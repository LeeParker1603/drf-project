# Онлайн-платформа обучения (DRF Project)

Проект полностью контейнеризирован с помощью Docker и Docker Compose. Включает в себя веб-приложение Django, базу данных PostgreSQL, кэш/брокер Redis и воркер Celery для фоновых задач.

## Требования для запуска
* Установленный и запущенный [Docker Desktop](https://docker.com)

## Инструкция по запуску приложения

1. **Клонируйте репозиторий к себе на компьютер:**
   ```bash
   git clone https://github.com/LeeParker1603/drf-project/
   cd drf-project
   ```

2. **Настройте переменные окружения:**
   Создайте файл `.env` в корневой директории на основе шаблона `.env.example`. Для корректной работы внутри изолированной сети Docker обязательно укажите следующие параметры хостов:
   ```ini
   HOST=db
   CELERY_BROKER_URL=redis://redis:6379/0
   CELERY_RESULT_BACKEND=redis://redis:6379/0
   ```

3. **Соберите образы и запустите все сервисы единой командой:**
   ```bash
   docker compose up -d --build
   ```

4. **Создайте суперпользователя для доступа к админ-панели:**
   ```bash
   docker compose exec web python manage.py createsuperuser
   ```

После выполнения этих шагов приложение будет доступно в браузере по адресу: `http://localhost:8000/`

## Управление проектом

* **Просмотр логов в реальном времени:**
  ```bash
  docker compose logs -f
  ```
* **Остановка всех контейнеров приложения (с сохранением данных в volumes):**
  ```bash
  docker compose down
  ```
* **Полный сброс контейнеров и очистка баз данных:**
  ```bash
  docker compose down -v
  ```
  
## 🚀 Автоматический деплой (CI/CD через GitHub Actions)

В проекте настроен автоматический pipeline (`.github/workflows/action.yml`). При каждом `push` или `pull_request` в ветки `main` или `develop` робот автоматически запускает блокирующие проверки.

### Этапы конвейера (Pipeline):
1. **Test:** Автоматический прогон тестов Django (`python manage.py test`). Если тесты падают, сборка блокируется.
2. **Lint:** Проверка качества и форматирования кода линтером `flake8 .` на соответствие стандартам PEP 8.
3. **Build & Deploy:** При успешном прохождении прошлых этапов (и только при событии `push`), GitHub Actions безопасно подключается к удаленному серверу по SSH, обновляет кодовую базу, генерирует рабочий `.env` из GitHub Secrets и перезапускает Docker-контейнеры.
